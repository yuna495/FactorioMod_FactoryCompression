# Factory Compression

Factorio 2.0向けのUPS対策MODです。

大量の同種設備を、少数の高性能なUPS版設備へ置き換えることで、同等の生産能力を保ちながらエンティティ数とクラフト完了回数を減らすことを目的としています。

## 基本方針

Factory Compressionは、既存設備を直接書き換えません。
元設備とは別に、赤い識別表示付きのUPS版設備、UPS版設備レシピ、一括処理レシピを自動生成します。

倍率を`N`とした場合、UPS版設備一台で通常設備`N`台分に近い能力を再現します。
初期値は10倍です。

## 対応設備

初期版では、次の最終Tier設備を対象にします。

* 組立機
* 製錬炉
* ソーラーパネル
* 蓄電池
* ボイラー
* 熱交換器
* 蒸気機関
* 蒸気タービン
* 原子炉
* Space Ageの給熱塔

ボイラーと熱交換器は`boiler`系設備として扱います。
蒸気機関と蒸気タービンは`generator`系設備として扱います。
原子炉と給熱塔はどちらも`reactor`ですが、隣接ボーナスの有無で扱いを分けます。

## 対象外

初期版では、次の設備は生成しません。

* 採掘機、ポンプジャック、資源エンティティ
* ベルト、地下ベルト、分配器
* インサータ、ローダー
* 物流ロボット、建設ロボット、ロボポート
* パイプ、地下パイプ、ポンプ、タンク
* ヒートパイプ
* `burner-generator`
* `fusion-generator`
* `fusion-reactor`
* `electric-energy-interface`
* runtimeスクリプトで性能制御される特殊設備

UPS原子炉やUPS給熱塔は通常ヒートパイプへ接続できる前提です。
ただし、高出力構成では通常ヒートパイプ側が熱輸送のボトルネックになる可能性があります。

## 製造設備

組立機や炉では、設備本体の`crafting_speed`は原則として変更しません。
かわりに、材料数と成果物数を`N`倍したUPS版一括処理レシピを生成します。

一回のクラフトで通常レシピ`N`回分をまとめて処理するため、生産量を維持しつつクラフト完了回数を減らします。

UPS版一括処理レシピは専用カテゴリへ所属します。
通常設備にはこの専用カテゴリを追加しないため、通常設備がUPS版一括処理レシピを実行することはありません。

### 炉について

Factorioの炉は、組立機のようにレシピを手動選択しません。
投入された材料から、解禁済みで処理可能なレシピを自動選択します。

UPS版炉もこの仕組みを使います。
そのため、UPS版炉へ鉱石を入れるには、対応するUPS版一括処理レシピが解禁済みである必要があります。

## 発電・蓄電・熱設備

発電・蓄電設備には一括処理レシピを生成しません。
設備プロトタイプの性能値を直接スケールします。

例:

* ソーラーパネルの発電量を`N`倍
* 蓄電池の容量、充電速度、放電速度を`N`倍
* ボイラーや熱交換器の熱出力と流体ボックス容量を`N`倍
* 蒸気機関や蒸気タービンの流体消費量を`N`倍
* 原子炉の燃料消費を`N`倍し、内部隣接ボーナス損失の補正として熱出力を`N × 1.2`倍
* 給熱塔の熱出力と燃料消費を`N`倍

原子炉の1.2倍補正は、圧縮によって失われる原子炉群内部の隣接ボーナスを部分的に補うための近似です。
給熱塔にはこの補正を適用しません。

## 研究と解禁

UPS版レシピは、研究効果として直接解禁しません。
runtimeで次のAND条件を満たす場合だけ、forceごとに解禁します。

* 対応するUPS研究が完了している
* 元レシピが解禁済みである

UPS版設備レシピでは、元設備アイテムを作るいずれかの元レシピが解禁済みであることを条件にします。
UPS版一括処理レシピでは、対応する元レシピそのものが解禁済みであることを条件にします。

これにより、UPS研究だけを先に終えても、元設備や元レシピを未解禁のままUPS版だけが使える状態にはなりません。

### 研究コスト

研究パックは環境によって自動決定します。
MOD追加の研究パックは要求しません。

Space Ageなし:

* `automation-science-pack`
* `logistic-science-pack`
* `military-science-pack`
* `chemical-science-pack`
* `production-science-pack`
* `utility-science-pack`
* `space-science-pack`

Space Ageあり:

* 上記7種
* `metallurgic-science-pack`
* `electromagnetic-science-pack`
* `agricultural-science-pack`
* `cryogenic-science-pack`
* `promethium-science-pack`

要求数は、各パック`N × 5000`個です。
倍率10倍なら各50,000個になります。

## 表示整理

UPS版一括処理レシピは、プレイヤーの製作一覧を圧迫しないよう`hide_from_player_crafting = true`を設定します。

完全な`hidden`扱いにはしないため、UPS版組立機やUPS版炉などからは選択または自動選択できます。
Factoriopediaでは、一括処理レシピの大量表示を避けるため、一括処理レシピを非表示にします。

## 設定

起動時設定で変更できます。

* UPS倍率: 5倍、10倍、20倍、50倍
* 詳細ログの有無
* UPS設備レシピに要求する速度モジュール3の数
* UPS設備レシピに要求する生産力モジュール3の数
* UPS設備レシピに要求する効率モジュール3の数

対象モジュールアイテムが存在しない環境では、その材料だけをレシピから除外します。

## 他MOD対応

Factory Compressionは、`data-final-fixes`段階で設備とレシピを走査し、可能な範囲で他MOD設備にも自動対応します。

ただし、特殊なruntime制御を持つ設備、安全に倍率変更できない設備、固定レシピ設備、材料や成果物を安全に一括化できないレシピは除外します。
除外理由はFactorioログへ出力します。

必要に応じて、compatibility定義で設備やレシピごとの個別対応を追加できる構造にしています。

## 注意点

このMODは開発初期版です。
大規模工場や複数MOD環境で使う場合は、事前に小さなセーブで挙動を確認してください。

UPS版炉へ鉱石を入れられない場合は、次を確認してください。

* UPS研究が完了しているか
* 元の製錬レシピが解禁済みか
* MOD更新後にFactorioを再起動しているか
* 既存セーブで技術効果の再適用が行われているか

## 開発メモ

詳しい仕様は`SPEC.md`を参照してください。

実装方針:

* データステージでプロトタイプを生成する
* runtimeではレシピ解禁状態の同期だけを行う
* 毎tick処理で生産を代替しない
* 既存設備を直接変更しない
* 対応できない設備やレシピは黙って無視せずログに出す
