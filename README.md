# Factory Compression

Factory Compressionは、Factorio 2.0向けのUPS対策MODです。

大量の同種設備を、少数の高性能なUPS版設備へ置き換えることで、通常設備`N`台分に近い生産・発電能力を少ないエンティティ数で扱うことを目的にしています。初期倍率は10倍で、起動時設定から5倍、10倍、20倍、50倍を選べます。

このMODは開発初期版です。正式な確認対象はFactorio 2.0 stableです。Factorio 2.1 experimentalでも可能な範囲で動作するようにしていますが、初期版の動作保証対象ではありません。

## 概要

Factory Compressionは既存設備を直接書き換えません。

元設備とは別prototypeとして、赤い識別表示付きのUPS版設備、配置アイテム、設備製作レシピ、一括処理レシピ、研究を自動生成します。

製造設備では、設備本体の`crafting_speed`を原則として変更せず、材料数と成果物数を`N`倍した一括処理レシピで処理量を増やします。

発電、蓄電、熱設備では一括処理レシピを作らず、prototype上の発電量、蓄電容量、熱出力、流体使用量などを安全に確認できる範囲で倍率化します。

## 対応設備

初期版では、以下の最終Tier候補を対象にします。

* 組立機
* 製錬炉
* ソーラーパネル
* 蓄電池
* ボイラー
* 熱交換器
* 蒸気機関
* 蒸気タービン
* 原子炉
* Space Ageの給熱塔

`next_upgrade`を持つ設備は、原則としてまだ上位Tierがあるものとして対象外にします。`next_upgrade`だけでは特殊設備、内部設備、runtime制御設備を完全には判別できないため、判定不能なものは性能変換の検証に失敗した時点で除外し、理由をFactorioログへ出します。

`hidden`や`hidden_in_factoriopedia`だけを根拠にした自動除外は初期版では追加していません。他MODの正規設備が表示制御だけを目的にこれらを使う可能性があるためです。個別の誤判定は`compatibility.lua`のwhitelist/blacklistで補正する方針です。

初期版では以下を生成しません。

* 採掘機、ポンプジャック、資源エンティティ
* ベルト、地下ベルト、分配器
* インサータ、ローダー
* 物流ロボット、建設ロボット、ロボポート
* パイプ、地下パイプ、ポンプ、タンク
* ヒートパイプ
* `burner-generator`
* `fusion-generator`
* `fusion-reactor`
* `electric-energy-interface`
* runtimeスクリプトで性能制御される特殊設備

## 一括処理の仕組み

UPS版製造設備は、元設備が使えるクラフトカテゴリに対応したFactory Compression専用カテゴリだけを持ちます。通常設備には専用カテゴリを追加しないため、通常設備がUPS版一括処理レシピを実行することはありません。

一括処理レシピでは、元レシピの材料量と成果物量を`N`倍し、製造時間、確率、温度、品質関連設定、表示順、主成果物、触媒・統計・生産力関連属性は可能な限り元レシピから継承します。数量上限や非スタック品など、安全に一括化できないレシピは生成しません。

炉は手動でレシピを選択せず、投入された材料から解禁済みレシピを自動選択します。UPS版炉でもこの挙動を維持し、`fixed_recipe`や毎tickの擬似生産処理は追加しません。

## 研究と解禁

UPS版設備レシピとUPS版一括処理レシピは、研究効果として直接解禁しません。runtimeで以下のAND条件を満たす場合だけ、forceごとに解禁します。

* 対応するFactory Compression研究が完了済みである
* 元設備または元レシピが解禁済みである

UPS版設備レシピでは、元設備アイテムを主成果物として作る正規製作レシピのいずれかが解禁済みであることを条件にします。リサイクルレシピ、副産物として設備アイテムを返すだけのレシピ、`hidden = true`の内部レシピ、主成果物を安全に判定できないレシピは、元設備の正規製作レシピとして扱いません。

他MODが複数の正規製作レシピを提供する場合は、そのうちいずれかが解禁済みならUPS版設備レシピも解禁できます。正規製作レシピを判定できない設備は、勝手に常時解禁せず、解禁元なしとして安全側に倒し、理由をログへ出します。

解禁同期は以下のタイミングで行います。

* 新規ゲーム開始時
* MOD構成変更時、起動時設定変更後
* 研究完了時
* 研究取り消し時
* 技術効果の再適用時
* force作成、リセット、統合時
* UPS版設備の設置、ロボット設置、スクリプト生成、復活時

毎tick監視や短周期の全走査は行いません。

## 表示と生産統計

生成設備、配置アイテム、設備製作レシピ、一括処理レシピの表示名は、元prototypeの`localised_name`があればそれを使い、ない場合は`entity-name`、`item-name`、`recipe-name`、`fluid-name`などのlocaleキーへフォールバックします。内部prototype名を翻訳済み文字列として扱わないようにしています。

UPS版一括処理レシピには`hide_from_player_crafting = true`を設定します。これはプレイヤーの製作一覧だけを隠し、設備のレシピ選択や炉の自動選択は維持します。

Factoriopediaの大量表示を避けるため、一括処理レシピには`hidden_in_factoriopedia = true`を設定します。UPS版設備、配置アイテム、設備製作レシピ、研究は識別可能な状態を維持します。

`hide_from_stats = true`は設定しません。Factorioのレシピprototype仕様上、このフィールドはアイテム/流体の生産統計からレシピを隠すため、UPS版の材料消費や成果物生産そのものが統計から消える可能性があります。

一括処理レシピは通常レシピとは別prototypeです。そのため、アイテム・流体単位の生産/消費統計は実際に消費・生産した同じアイテム/流体へ計上される想定ですが、レシピ単位の統計を元レシピと同一項目へ統合することは行いません。統計補正用の`on_tick`処理や、クラフト完了ごとの重いruntime補正は追加していません。

## 他MOD対応

Factory Compressionは`data-final-fixes`段階でprototypeを走査し、他MODが追加した設備やレシピにも可能な範囲で自動対応します。

ただし、他MODも`data-final-fixes.lua`で後からprototypeを変更する場合、Factory Compressionが必ず最後に実行される保証はありません。後から行われたprototype変更はUPS版へ反映されない可能性があります。

正式対応MODを追加する場合は、optional dependencyなどで読み込み順を指定することがあります。現時点では個別の正式対応MODはないため、不要なoptional dependencyは追加していません。全MODに対する完全な順序保証はできません。

特殊なruntime制御設備、安全に倍率変更できない設備、固定レシピ設備、安全に一括化できないレシピは除外します。除外理由はFactorioログへ出力します。

## 発電・流体・熱設備の制限

発電、蓄電、熱設備はprototype性能を倍率化しますが、設備サイズ、接続位置、接続方向、接続口数は元設備から変更しません。

ボイラー、熱交換器、蒸気機関、蒸気タービン、原子炉、給熱塔では、流体ボックス容量や熱容量を倍率化しても、水、蒸気、熱の搬送口数は増えません。高倍率ほど、通常設備`N`台との等価性は崩れやすくなります。

特に20倍、50倍では、配管、ポンプ、ヒートパイプ、タービン比率、熱交換器比率が先にボトルネックになる可能性が高いため、実地確認が必要です。

## 原子炉の近似

UPS原子炉では、通常原子炉群を圧縮したときに失われる内部隣接ボーナスを補うため、隣接ボーナスを持つ燃料式`reactor`に限り`energy_source.effectivity`を1.2倍します。

この1.2倍は完全な等価再現ではなく近似です。通常原子炉`N`台の本来の平均隣接ボーナスは配置によって変わります。UPS原子炉同士も隣接ボーナスを得るため、UPS原子炉の配置によって出力差が生じます。

そのため、通常原子炉`N`台と完全に同じ燃料消費、熱出力、熱流量を保証しません。給熱塔にはこの1.2倍補正を適用しません。

## remote interface

他MODがruntimeで元レシピの解禁状態を変更した場合、Factory Compressionはそれを自動検出できません。毎tick監視は行わないため、必要に応じて以下のremote interfaceで明示的に再同期してください。

```lua
remote.call("factory-compression", "sync_force", "player")
remote.call("factory-compression", "sync_force", game.forces.player)
remote.call("factory-compression", "sync_all_forces")
```

`sync_force`はforce名文字列または`LuaForce`を受け取り、成功時に`true`、forceが見つからない場合に`false, "force-not-found"`を返します。

このinterfaceは解禁状態を再計算するだけで、prototypeや保存データ構造を変更しません。forceごとに独立して同期するため、マルチプレイでも他forceの解禁状態を混ぜません。

## 既知の制限

* runtimeから変更された元レシピの解禁状態は、自動検出できません。
* 一括処理レシピは別recipe prototypeなので、レシピ単位の統計は元レシピへ統合されません。
* `data-final-fixes`後に他MODがprototypeを変更した場合、その変更はUPS版に反映されないことがあります。
* `next_upgrade`だけでは特殊設備や内部設備を完全に判定できません。
* runtimeスクリプト制御設備は自動判定できない場合があります。
* 流体、蒸気、熱の搬送能力は高倍率でボトルネックになりやすいです。
* 原子炉の1.2倍補正は配置依存の隣接ボーナスを完全再現しません。
* ヒートパイプ、核融合発電、採掘、搬送、物流、流体輸送設備は初期版では対象外です。

## テスト時の注意

大規模工場や複数MOD環境で使う前に、小さなセーブで確認してください。

特に以下を確認してください。

* 日本語・英語環境で、UPS版設備、アイテム、設備レシピ、一括処理レシピが内部名ではなく表示名で出ること
* Space Age/Qualityのリサイクルレシピが、設備レシピの解禁条件に混入しないこと
* 通常レシピ未解禁時にUPS設備レシピが解禁されないこと
* 通常レシピ解禁後にUPS設備レシピが解禁されること
* UPS一括処理レシピの材料消費と成果物生産が、アイテム/流体単位の統計へ計上されること
* 一括処理レシピがプレイヤー製作一覧とFactoriopediaに大量表示されないこと
* UPS版炉が、解禁済みの一括製錬レシピを材料投入から自動選択できること
* 20倍、50倍の発電、流体、熱設備で搬送ボトルネックが起きないこと

Factorioを実際に起動して検証していない変更では、ゲーム内テスト済みとは扱わないでください。
